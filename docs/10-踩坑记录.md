### [坑 1] vitest/esbuild 不做类型检查，类型错误到运行时才暴露

- **现象**：`geometry.ts` 的 `mirror()` 把动态障碍对象当坐标展开，`d.cell` 为 undefined 抛 TypeError；tsc 当时并不报错（被 `mirror` 的 `{x,y}` 返回类型"掩盖"）。
- **原因**：vitest 用 esbuild 转译（不做类型检查），且泛型函数 `flatMap` 对字面量数组的上下文类型推断丢失（motion 被推断为 string）。两道防线同时失效。
- **解决**：a) 动态障碍镜像单独写 `mirrorObstacle()`（cell 与 target 都镜像）；b) 数组字面量用 `satisfies DynamicObstacle[]` 恢复上下文类型；c) 校验器必须作为每次改动的闸门（npm run check 先于提交）。
- **状态**：已解决
- **日期**：2025-xx-xx

### [坑 2] 中心对称镜像源点不能互为镜像

- **现象**：`mirrorCells([{x:3,y:3},{x:12,y:8}])` 校验报"静态障碍重叠"——(3,3) 与 (12,8) 恰为对称点对，各自展开两次。
- **原因**：源点集合本身自对称，flatMap 展开后每点出现两次。
- **解决**：换用互不成对的源点（(3,3)+(13,4)），并在注释中标注约束。
- **状态**：已解决
- **日期**：2025-xx-xx

### [坑 3] PowerShell Set-Content 默认非 UTF-8 编码，破坏源码文件

- **现象**：用 `(Get-Content -Raw) -replace ... | Set-Content` 修改 engine.test.ts 后，文件变成非法 UTF-8（中文注释乱码/损坏），vitest 报 "Transform failed: Expected ';' but found ':'"，read 工具也读不了。
- **原因**：Windows PowerShell 的 `Set-Content` 默认用系统 ANSI（GBK）编码写文件，而源码是 UTF-8。
- **解决**：**绝不**用 PowerShell 管道改写含非 ASCII 的源码文件；一律用 write/edit 工具。若必须用 pwsh 写文件，用 `[System.IO.File]::WriteAllText($path, $content, [System.Text.UTF8Encoding]::new($false))`。
- **状态**：已解决
- **日期**：2025-xx-xx

### [坑 4] 测试里用 Date.now() 当 rAF 时间戳，同一毫秒内 dt=0 时间不推进

- **现象**：engine 测试推进仿真时间时用 `cb(Date.now())`，游戏逻辑时间几乎不增长（死循环被 guard 截断），蛇从未移动。
- **原因**：`Date.now()` 在循环内连续调用返回同一毫秒值 → `dt = ts - lastTs = 0` → 累积器不增加 → tickLogic 不执行。
- **解决**：mock 的 rAF 回调使用**递增时间戳**（`ts += 16.67`），与真实 rAF 行为一致。
- **状态**：已解决
- **日期**：2025-xx-xx

### [坑 5] 双人测试中 P2 无人操作会自己撞墙/撞障碍，干扰复活流程验证

- **现象**：coop 测试推进 10 秒验证复活时，P2 自动撞墙（或撞上丛林地图 (8,9) 的脉冲障碍）→ 双死 → gameover，复活流程无法验证。
- **原因**：AI 蛇不会自己转向；测试时间尺度（10s+）远超 P2 撞墙所需（2~3s）。
- **解决**：a) 注册**测试专用空地图**（registerMap/registerTheme 动态注册）；b) 用"绕圈器"helper 基于逻辑时间每 1s 给 P2 转向 90°，路径（left 6 格→up 6 格→right 6 格→down 6 格）精确不撞墙。
- **状态**：已解决
- **日期**：2025-xx-xx

### [坑 6] 集成测试时间断言必须精确计算，不能"大概够"

- **现象**：`circle(10.5)` 后断言 `invincible` 失败，实际是 `alive`。
- **原因**：P1 于 elapsed≈10.5s 复活（保护期 2s 到 12.5s），circle(10.5) 恰好把时间推到 12.5s——断言时刻保护期刚好走完。数学上完全正确，是测试预算错了。
- **解决**：先推导精确时间线（撞墙时刻、复活时刻、保护期结束时刻），再选断言窗口（circle(9.9) 落在保护期内）。
- **状态**：已解决
- **日期**：2025-xx-xx

### [坑 7] React effect 中途插入 return 会截断整个 effect

- **现象**：给 GameCanvas 的 useEffect 补"清理 renderer 单例"逻辑时，在 effect 中间写了一个 `return () => {...}`，导致其后的订阅/循环代码全部不执行（静默失效，无报错）。
- **原因**：useEffect 回调里的 `return` 就是清理函数，中途 return = 提前结束 effect 主体。
- **解决**：把清理逻辑合并到 effect 末尾唯一的 `return () => {...}` 中；改 effect 后立即人工检查"主体代码是否可达"。
- **状态**：已解决
- **日期**：2025-xx-xx

### [坑 8] 编辑工具与 PowerShell 混用导致"file changed"冲突

- **现象**：edit 工具报 "file changed since it was read"——文件在 read 之后被其他途径（pwsh 脚本/前一次失败编辑）改动。
- **原因**：read 快照过期；两套写入通道互相覆盖。
- **解决**：对同一文件同一轮只走一条通道（write/edit 或 pwsh 二选一）；报错后重新 read 再编辑。
- **状态**：已解决
- **日期**：2025-xx-xx

### [坑 9] engine.restart() 未取消旧 rAF 循环 → 双倍速

- **现象**：代码审查发现 restart()（含暂停重开/死亡重开）调用 start() 时没有 `cancelAnimationFrame(this.raf)`，旧 loop 与新车循环同时跑 → 移动双倍速、elapsed 错乱。
- **原因**：loop 每帧末尾自行调度下一次 rAF，restart 未打断旧调度链。
- **解决**：start() 开头先 `cancelAnimationFrame(this.raf)`；加回归测试（1 秒内蛇只走约 6 格，双循环会翻倍）。
- **状态**：已解决
- **日期**：2025-xx-xx

### [坑 10] 结算界面"再来一局"若直接 restart 会与 screen effect 双 start

- **现象**：GameOverOverlay 的 replay 直接调 engine.restart()，而 GameCanvas 的 screen effect 在 screen 变化回 playing 时也会 start() → 两次初始化（数值无碍但违背单一入口）。
- **原因**：两条代码路径都触发 start，职责重叠。
- **解决**：replay 只 `setScreen("playing")`，统一由 screen effect 启动；R 键同样只切 screen。
- **状态**：已解决
- **日期**：2025-xx-xx

### [坑 11] 重开游戏后 HUD 残留上一局分数

- **现象**：restart 后 state 事件只设 paused:false，scores/combos 仍显示上一局值，直到吃到第一个食物才刷新。
- **原因**：缺少"开新局清空 HUD"的联动。
- **解决**：state==="playing" 事件处理里调用 `resetHud()`（归零分数/连击/复活条）。
- **状态**：已解决
- **日期**：2025-xx-xx

# 08 · 协作开发规范（防坑机制）

> 本文件定义"通过 AI 协作开发本项目"的流程规范与已知坑清单。
> 目的：规避两类风险——**AI 协作特有的坑**（失忆/幻觉/漂移）与**技术栈固有的坑**（浏览器/音频/字体/性能）。

## 1. 核心原则

1. **小步前进**：一个阶段一个功能，每步验证，随时可回滚
2. **校验流水线是防 AI 幻觉的第一道闸**：AI 写出的代码必须通过类型检查 + 测试 + 数据校验才能提交
3. **文档先行**：改设计先改 docs，再改代码（已约定于 06 文档）
4. **AI 动手前先读文档**：防止 AI"失忆"（对话过长忘记早期决策）
5. **报错原文反馈**：报错时把错误信息原文给 AI 修复，禁止"推倒重写碰运气"

## 2. Git 工作流

- 仓库：`https://github.com/xch66666/Greedy-snake`（main 为唯一长期分支）
- **提交时机**：每个阶段完成 + 每次会话结束（防 AI 失忆、防丢失）
- **提交规范**：message 前缀 `feat:` / `fix:` / `docs:` / `refactor:` / `style:`，一条 commit 一个逻辑单元
- **禁止**：未通过校验流水线的提交；超过 200 行改动的一次性大提交（须拆分）
- **回滚**：任何时刻 `git log` 找到上一个好版本，`git revert` 或 `git reset` 即可回到安全点
- 换行规范：后续加入 `.gitattributes`（`* text=auto`）统一 LF/CRLF，消除换行噪音

## 3. 校验流水线（每次改动必跑，AI 必须自己跑通）

```
npm run check =
  tsc --noEmit      # 类型检查（防 API 幻觉：写错字段/方法立刻暴露）
+ vitest run        # 单元测试（逻辑层全覆盖）
+ validate          # 地图/主题数据校验器（数据写错立刻报错）
+ eslint            # 代码规范
```

- 任何一步失败 → 不允许提交、不允许进入下一阶段
- AI 写代码后**必须自行运行**该流水线，把结果汇报给用户

## 4. AI 协作规则（防失忆 / 防漂移 / 防范围蔓延）

| 规则 | 说明 |
|---|---|
| 会话开始先读文档 | 每轮工作开始，AI 先读 README + 01 定案 + 涉及模块文档，复述关键决策要点 |
| 方案先行 | 重大改动前，AI 先给出改动方案（涉及文件、改动内容、风险），用户确认后动手 |
| 一次只做一件事 | 一个会话只做一个阶段/一个功能，不做"顺手"改动 |
| 查证代替记忆 | AI 不确定的 API/语法必须查证（官方文档 / 类型定义），禁止凭记忆编造 |
| 完成汇报 | 每轮结束汇报：改动文件清单 / 如何验证 / 已知风险 / 下一步建议 |
| 需求蔓延控制 | 用户临时想法默认记入后置项，不实现，除非明确说"本期要做" |
| 未知问题上报 | AI 遇到超出文档范围的问题，先问用户，不擅自改设计 |

## 5. 已知坑清单（技术栈预警，遇到先查这里）

| # | 坑 | 对策 |
|---|---|---|
| 1 | 浏览器自动播放策略：无用户手势前 AudioContext 不可播放 | 首次点击/按键后才创建音频上下文；BGM 必须等用户进入游戏（有交互）后启动 |
| 2 | 中文像素字体体积大（全字符集可达数 MB） | Fusion Pixel 按需子集化（仅打包用到的字符）或懒加载；`font-display: swap` |
| 3 | GitHub Pages 子路径部署资源 404 | `vite.config` 的 `base` 设为仓库路径（如 `/Greedy-snake/`），部署后验证资源路径 |
| 4 | 键盘 key repeat + 双人按键 | 输入用 keydown/keyup **状态机**（不是计数）；`event.repeat` 标记忽略；WASD 与方向键分区天然不冲突 |
| 5 | React StrictMode 开发模式双执行 effect | 引擎初始化/销毁必须**幂等**：effect 清理函数完整销毁引擎，防止双实例/事件泄漏 |
| 6 | `pixelated` 放大后边缘半透明像素发虚 | 整数倍缩放 + 画布内留 1px 安全边距；禁止非整数倍 |
| 7 | localStorage 隐私模式/配额满写入失败 | 读写全 try/catch + 内存兜底（本次会话内仍有效），不崩溃 |
| 8 | 固定步长累积器溢出（长时间卡顿后追赶） | 累积器设上限（如 250ms），超出丢弃而非追赶，防"瞬移" |
| 9 | Web Audio 节点泄漏（每次吃食物新建节点） | 统一 audio 管理器：节点用完 `stop()` + `disconnect()`；切图时清空上一主题节点 |
| 10 | 双人 HUD 高频更新触发 React 重渲染 | score 等事件聚合到 rAF 批量写入，Zustand 只存低频状态 |
| 11 | 切页签回来 delta 爆炸 | `visibilitychange` 自动暂停（已设计于 05 文档） |
| 12 | Fusion Pixel 为 OFL 开源许可 | 保留许可文件；本项目开源则无冲突，闭源分发需附许可声明 |
| 13 | Canvas 字体未加载完成就绘制中文 | 字体 `document.fonts.ready` 后再进游戏/绘制文本，或绘制前 `fonts.load()` |
| 14 | 双人复活倒计时与暂停叠加 | 暂停时冻结倒计时（统一时间源暂停），恢复后继续，不跳秒 |

> 新踩到的坑 → 立即回填本表（坑 + 对策），形成项目自己的"避坑手册"。

## 6. 会话结束检查单（AI 每轮收尾必做）

- [ ] 校验流水线全绿（tsc + vitest + validate + eslint）
- [ ] 涉及规则/类型/界面的改动已同步到 docs（03/04/07 等）
- [ ] `git add -A` + 规范 message 提交 + `git push`
- [ ] 汇报：改动清单 / 验证方式 / 已知风险 / 下一步建议

## 7. 用户侧配合（很简单，但很关键）

1. 每轮验收：在浏览器实测 AI 交付的功能，对照 06 文档的验收标准
2. 发现不对 → 把现象描述给 AI（截图可用文字描述代替），AI 修
3. 新想法 → 先让 AI 记入后置项，避免打断当前阶段
4. 关键节点（阶段验收）后，在 GitHub 上确认提交历史完整

# 04 · 架构设计

## 1. 分层架构（五层 + 横切）

```
┌──────────────────────────────────────────────────────┐
│  ui /       React 壳：菜单、选图、HUD、暂停、结算      │
│  boot/      加载管理器（资源清单 + 进度）               │
├──────────────────────────────────────────────────────┤
│  桥接层      GameCanvas 组件：引擎 ↔ React 唯一通道     │
│             （事件订阅 → Zustand；命令口 → EngineAPI）  │
├──────────────────────────────────────────────────────┤
│  render/    Canvas 渲染：renderer / effects / easing / │
│             staticLayer（离屏预渲染）                  │
├──────────────────────────────────────────────────────┤
│  game/      纯 TS 逻辑：core（snake/food/collision/    │
│             rules）/ maps / themes / engine（主循环）   │
├──────────────────────────────────────────────────────┤
│  storage/   localStorage 存档（版本化 + 校验）          │
└──────────────────────────────────────────────────────┘
  横切：errorReporter（错误收集）、debug（F1 调试面板）
```

铁律：
- **逻辑层不碰 DOM/Canvas/React**（纯函数，可单测）
- **渲染层只消费 MapData + Theme**，不认识具体地图
- **React 只能通过 EngineAPI 命令游戏**，游戏状态只通过事件流出
- **地图/主题文件里只有数据**，没有任何逻辑与绘制代码

## 2. 目录结构（目标：每个文件 100~300 行，职责单一）

```
src/
```

## 3. 数据流（单向）

```
engine（固定步长推进逻辑）
   │  发射 GameEvent：eat / score / death / revive / gameover / state
   ▼
桥接层（GameCanvas 组件内订阅）
   ▼
Zustand store（低频状态：分数、连击、模式、地图、难度、蛇子状态）
   ▼
HUD / 菜单 / 暂停 / 结算 响应式更新
```

反向：React 只调 `engine.start(mapId, mode, difficulty)` / `pause()` / `resume()` / `restart()` / `destroy()`。

## 4. 引擎设计

- **固定时间步长**（如 60Hz 逻辑 tick），渲染帧做插值 → 逻辑确定、动画流畅
- **统一时间源**：`performance.now()`，蛇与动态障碍共用，杜绝多时钟错位
- **切页签自动暂停**：`visibilitychange` → 暂停并记录状态，避免 delta 爆炸
- **单帧错误隔离**：每帧 try/catch，连续 N 帧失败停止循环并报错（见 05）

## 5. 核心接口草案（编码阶段第一步正式化并评审）

```ts
// 地图（纯数据）
interface MapData {
  id: string
  name: string
  grid: { w: number; h: number }
  spawn: { x: number; y: number }
  staticObstacles: Cell[]
  dynamicObstacles: DynamicObstacle[]
  themeId: string
  decorSeed: number
}

// 动态障碍
interface DynamicObstacle {
  cell: Cell
  motion: "pulse" | "patrol" | "gate" | "drift"
  params: { range: number; speed: number; phase: number }
}

// 主题（纯数据，见 02 文档完整字段）
interface Theme {
  id: string
  palette: { ... }          // 8~10 色调色板
  obstacleStyle: "vine" | "stone" | "prism" | "coral"
  snakeStyle: { pattern: ...; head: ... }
  anim: { eatParticle: ...; dur: number }
  bgm: { tempo: number; scale: string }
  // ...
}

// 引擎事件（向外流出的唯一通道）
type GameEvent =
  | { type: "eat"; cell: Cell; player: 1 | 2 }
  | { type: "score"; player: 1 | 2; score: number; combo: number; multiplier: number }
  | { type: "death"; player: 1 | 2; reason: string }
  | { type: "revive"; player: 1 | 2 }
  | { type: "reviveCountdown"; player: 1 | 2; remaining: number }
  | { type: "gameover"; winner?: 1 | 2 | "draw" }
  | { type: "state"; state: EngineState }

// 引擎对外命令口（React 唯一入口）
interface EngineAPI {
  start(mapId: string, mode: "solo" | "coop", difficulty: Difficulty): void
  pause(): void
  resume(): void
  restart(): void
  destroy(): void
  on(ev: GameEvent, handler: (e: GameEvent) => void): () => void
}

// 存档（版本化）
interface SaveData {
  version: 1
  settings: {
    sfxVolume: number
    musicVolume: number
    quality: "high" | "mid" | "low"
    difficulty: "casual" | "normal" | "hard"
  }
  stats: {
    bestScores: Record<string, number>       // 每图单人最高分（key = mapId）
    bestScoresCoop: Record<string, number>   // 每图双人最高分（双方合计）
    totalFood: number
    playCount: number
  }
}
```

## 6. 存档设计

| 项 | 定案 |
|---|---|
| 内容 | 设置（音量/画质/难度）+ 统计（每图最高分、总食物数、局数） |
| 格式 | 版本化 JSON（`version` 字段），未来加字段走迁移函数，天然"不丢" |
| 写入 | 防抖写入 + 页面隐藏时强制 flush，单 key 存储避免半写坏档 |
| 校验 | 读入时 schema 校验；损坏 → 提示"存档损坏"并提供"重建默认存档"（呼应"可删不丢"） |
| 删除 | 设置页提供"删除存档"按钮（可删） |
| 原则 | 只存结果与设置，不存游戏内部瞬时状态 |

## 7. 双人模式对架构的影响

| 层 | 增量 |
|---|---|
| 输入 | 单控制器 → 双控制器（P1=WASD，P2=方向键），各自 2 帧缓冲 |
| 逻辑 | 双蛇状态机（ALIVE / GHOST_WAITING / INVINCIBLE），复活判定、双死判定 |
| 渲染 | 绘制两条蛇（同主题不同配色），死亡幽灵特效 |
| HUD | 双分数显示，复活倒计时提示 |
| 地图 | 同屏共用地图，无需扩大网格（安全复活点需避开两蛇） |

## 8. 约定

- 类型定义集中在 `types.ts` / `schema.ts`，跨层引用不复制
- 纯逻辑必须可注入随机种子（`decorSeed`、食物生成），保证可测
- 新增地图 = 新增 1 个地图数据文件 + 1 个主题文件（可能复用主题），逻辑零改动

# 00 · 项目概览

## 项目定位

卡通像素风格的贪吃蛇小游戏：

- 画面丰富、色彩丰富、动效流畅（动效适中档）
- 支持多地图选择：4 张风格各异的地图
- 支持经典单人无尽模式与双人合作模式
- 深色为主，UI 跟随地图主题整体换肤
- 纯浏览器网页，无需安装、无需后端，本地存档

## 技术栈（已确认）

| 层 | 选择 | 理由 |
|---|---|---|
| 语言 | TypeScript | 多地图 + 主题数据结构的类型约束，防止数据写错 |
| 工程 | Vite + 模块化 | 热更新、文件拆分清晰、支持 TS |
| UI | React + Zustand | 组件化界面（菜单/选图/HUD）+ 轻量跨组件状态 |
| 游戏渲染 | Canvas 2D 自绘 | 动效控制力强，插值/粒子/发光都好做，性能足够 |
| 渲染策略 | 低分辨率 + `pixelated` 整数放大 | 像素风观感与性能双赢 |
| 存档 | localStorage + 版本化 JSON | 只需本地存档，支持"可删不丢" |
| 字体 | Fusion Pixel（缝合像素字体） | 开源、中文全支持、12px 整倍缩放 |
| 音效/音乐 | Web Audio 程序化生成 | 8-bit 音效 + 每主题 chiptune 循环，零音频文件 |
| 测试 | Vitest | 核心逻辑层是纯函数，测试成本低收益高 |

## 核心设计原则（5 条，开发时不得违背）

1. **逻辑与渲染彻底分离**：core 层是纯 TS 纯函数，不碰 DOM/Canvas，可独立测试
2. **地图 = 数据 + 主题引用**：地图文件里没有一行"怎么画"，主题文件里没有一行"游戏逻辑"
3. **主题驱动渲染与 UI**：渲染器和 React 组件都只消费 Theme 接口，不认识具体地图，加第 5 张图零逻辑改动
4. **状态不进 React**：Canvas 内的一切高频状态不进 React，通过事件桥接，保证游戏循环不受 React 渲染周期影响
5. **单一事实来源**：一切设计决策以 `docs/` 文档为准；修改设计必须先改文档再改代码

## 决策记录

| 轮次 | 主题 | 结论 |
|---|---|---|
| 1 | 平台 / 后端 / 语言 / 工具 | 纯浏览器网页、只需本地存档、TypeScript、Vite 模块化 |
| 2 | 渲染 / UI 框架 | Canvas 2D 自绘（听推荐）、React |
| 3 | UI 风格 / 配色 / 动效 | 卡通像素、深色为主跟随地图换肤、动效适中（200~400ms） |
| 4 | 地图风格 | 丛林自然 / 暗黑地牢 / 极简几何 / 深海蓝光（4 张） |
| 5 | 地图差异化维度 | 配色、背景装饰、障碍布局、蛇身外观（不含玩法规则） |
| 6 | 网格形态 / 障碍 | 方形网格、中等视觉复杂度、动态障碍为主 |
| 7 | 体验保障 | 流畅性 / 布局自适应 / 加载动画 / 报错兜底四项机制 |
| 8 | 玩法与工具 | 操控手感、音效音乐、难度计分、模式、低配降级、中文字体、开发工具链 |
| 9 | 双人模式 | 合作模式、各自计分、10 秒复活、复活 2 秒保护、两蛇互穿不互伤 |
| 10 | 首发模式 | 经典单人无尽 + 双人合作（限时/关卡/对战后置） |
| 11 | 难度曲线 | 休闲 / 标准 / 困难三档预设 |

> 详细决策内容见 [01-设计定案.md](01-设计定案.md)
